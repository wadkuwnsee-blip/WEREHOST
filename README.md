# WEREHOST — Blood Moon Edition

เว็บเกม Werewolf แบบหลายผู้เล่น พัฒนาต่อจาก starter เดิมด้วย Node.js, Express, PostgreSQL และ Socket.IO

## ฟังก์ชันในเวอร์ชันนี้
- สมัครสมาชิกด้วยอีเมล/รหัสผ่าน และยืนยัน OTP 6 หลัก อายุ 10 นาที; รหัสผ่านต้องยาวอย่างน้อย 8 ตัว มีตัวพิมพ์ใหญ่ A–Z ตัวเลข 0–9 และอักขระพิเศษ
- เข้าสู่ระบบด้วยอีเมลและรหัสผ่าน
- Google Sign-In ผ่าน Google Identity Services (ต้องกำหนด `GOOGLE_CLIENT_ID`)
- ตั้งค่าเปลี่ยนชื่อผู้ใช้ เปลี่ยนรหัสผ่าน และออกจากระบบ
- สร้างห้อง/เข้าห้องด้วยรหัส 6 ตัว จำกัด 4–10 คน
- สุ่มบทบาท: หมาป่า, ชาวบ้าน, เซียร์, บอดี้การ์ด และยาจก
- บทบาทพิเศษไม่ซ้ำกันในหนึ่งเกม; ชาวบ้านเป็นบทบาทเติมตามจำนวนผู้เล่น
- หมาป่าเลือกกำจัด 1 คนต่อคืน, เซียร์ตรวจฝ่าย 1 คนต่อคืน, บอดี้การ์ดปกป้องคนละหนึ่งเป้าหมายตลอดเกม (ห้ามปกป้องเป้าหมายเดิมซ้ำ)
- ยาจกชนะทันทีเมื่อถูกโหวตออก
- โหวตช่วงกลางวันและแชทเรียลไทม์แยกตามห้อง
- UI ธีมดำ-แดง ใช้ฟอนต์ Noto Sans Thai และรองรับมือถือ

## บทบาทตามจำนวนผู้เล่น
- 4 คน: หมาป่า 1, เซียร์ 1, บอดี้การ์ด 1, ชาวบ้าน 1 (ยังไม่ใส่ยาจก เพราะจำนวนผู้เล่นไม่พอสำหรับบทบาทพิเศษทั้งห้า)
- 5 คน: หมาป่า 1, เซียร์ 1, บอดี้การ์ด 1, ยาจก 1, ชาวบ้าน 1
- 6–10 คน: บทบาทพิเศษ 4 บทบาทอย่างละ 1 และชาวบ้านเติมจำนวนที่เหลือ

## ติดตั้งและรัน
1. ต้องใช้ Node.js 20+ และ PostgreSQL
2. แตก ZIP และเปิด Terminal ในโฟลเดอร์โปรเจกต์
3. รัน `npm install`
4. คัดลอก `.env.example` เป็น `.env`
5. ตั้ง `DATABASE_URL` และ `JWT_SECRET`
6. ตั้งค่า SMTP เพื่อส่ง OTP จริง (หากไม่ได้ตั้งค่า SMTP ในโหมด development OTP จะถูกแสดงในหน้าเว็บและ Terminal เพื่อทดสอบเท่านั้น)
7. ตั้ง `GOOGLE_CLIENT_ID` จาก Google Cloud Console เพื่อเปิด Google Sign-In และเพิ่มโดเมนเว็บไซต์ใน Authorized JavaScript origins
8. รัน `npm start` แล้วเปิด `http://localhost:3000`

ระบบสร้างตารางและปรับ schema ผู้ใช้เดิมให้อัตโนมัติเมื่อเริ่มเซิร์ฟเวอร์

## ข้อกำหนดรหัสผ่าน
- รหัสผ่านตอนสมัครและตอนเปลี่ยนรหัสผ่านต้องมีอย่างน้อย 8 ตัวอักษร
- ต้องมีตัวอักษรพิมพ์ใหญ่ภาษาอังกฤษ A–Z อย่างน้อย 1 ตัว
- ต้องมีตัวเลข 0–9 อย่างน้อย 1 ตัว
- ต้องมีอักขระพิเศษ/เครื่องหมายวรรคตอนอย่างน้อย 1 ตัว เช่น ! @ # $ %
- ตรวจสอบทั้งฝั่งหน้าเว็บและเซิร์ฟเวอร์

## หมายเหตุสำคัญก่อนเปิดใช้งานจริง
- ห้องและสถานะเกมเก็บในหน่วยความจำของ process จึงหายเมื่อรีสตาร์ต และรองรับการ deploy แบบ instance เดียวเท่านั้น ควรย้ายไป Redis/PostgreSQL ก่อน scale หลาย instance
- การเปลี่ยนช่วงกลางคืน/กลางวันยังให้หัวหน้าห้องกดเอง ไม่มีตัวจับเวลาอัตโนมัติ
- แนะนำเพิ่ม rate limiting, CSRF/origin protection, moderation, reconnect recovery, automated tests และ logging ก่อนเปิดสาธารณะ
- Google Sign-In ต้องใช้ HTTPS บน production และตั้งค่า OAuth Client ID ให้ตรงโดเมน
- OTP ใน production ต้องกำหนด SMTP ให้สำเร็จ ระบบจะไม่แสดง OTP ในหน้าเว็บ

## โครงสร้าง
- `server.js` — API, authentication, game state, Socket.IO chat
- `public/index.html` — หน้าเว็บทั้งหมด
- `schema.sql` — schema เริ่มต้น
- `.env.example` — ตัวอย่าง environment variables


## อัปเดตเพิ่มเติม
- หัวหน้าห้องสามารถกด `ยกเลิกการสร้างห้อง` ได้ระหว่างที่ห้องยังอยู่ในสถานะรอผู้เล่น ระบบจะแจ้งผู้เล่นทุกคนและนำทุกคนออกจากห้อง
- เมื่อเริ่มเกมแล้ว จะไม่สามารถยกเลิกห้องผ่านปุ่มยกเลิกการสร้างได้

หมายเหตุ: Noto Sans Thai โหลดจาก Google Fonts จึงต้องเชื่อมต่ออินเทอร์เน็ตเพื่อแสดงฟอนต์ หากโหลดไม่ได้จะ fallback เป็น sans-serif


## ระบบผู้ดูแลระบบ (Admin Panel)
- เปิดหน้าแอดมินที่ `/admin.html` หรือกดปุ่ม Admin ในหน้า Lobby (จะแสดงเฉพาะบัญชีที่มี role=admin)
- Dashboard แสดงจำนวนสมาชิกทั้งหมด/ใช้งาน/ถูกระงับ/ผู้ดูแล และจำนวนห้อง/เกมที่กำลังเล่น
- จัดการสมาชิก: ค้นหาด้วยชื่อหรืออีเมล, ระงับ/ปลดระงับบัญชี, แต่งตั้ง/ถอนสิทธิ์ Admin
- จัดการห้อง: ดูห้องที่เปิดอยู่และปิดห้องได้ โดยผู้เล่นในห้องจะได้รับแจ้งเตือน
- ประวัติแอดมิน: บันทึกการระงับ/ปลดระงับสมาชิก, เปลี่ยนสิทธิ์ และปิดห้อง
- API ทุกเส้นทางของ Admin ตรวจสอบ role จาก PostgreSQL ทุกครั้ง ไม่เชื่อ role ที่ส่งมาจาก browser; Socket.IO ตรวจสอบสถานะบัญชีจากฐานข้อมูลก่อนเชื่อมต่อ

### วิธีตั้งค่า Admin คนแรก
1. สมัครบัญชีผู้ใช้ตามปกติด้วยอีเมลที่ต้องการเป็นผู้ดูแล
2. หยุดเซิร์ฟเวอร์
3. เปิด `.env` แล้วตั้ง `ADMIN_EMAIL` ให้ตรงกับอีเมลที่สมัครไว้ (ตัวอย่าง `ADMIN_EMAIL=you@example.com`)
4. เริ่มเซิร์ฟเวอร์ใหม่ด้วย `npm start` ระบบจะยกระดับบัญชีนั้นเป็น Admin อัตโนมัติ
5. เข้าสู่ระบบด้วยบัญชีดังกล่าว แล้วกดปุ่ม **Admin** หรือเปิด `/admin.html`

ข้อควรระวัง: เก็บ `.env` และสิทธิ์เข้าถึงฐานข้อมูลเป็นความลับ อย่าแชร์บัญชี Admin ให้ผู้อื่น และอย่าตั้ง `ADMIN_EMAIL` เป็นอีเมลที่ไม่ใช่ของผู้ดูแลที่เชื่อถือได้
